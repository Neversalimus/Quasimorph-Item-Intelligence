# Item Intelligence 1.7.42.4 — выпуск

Принятый Test3 переведён в стабильную версию. В игровом C# изменены только номер версии и маркер; локализация и алгоритмы совпадают с проверенным Test3. Комплект содержит исходники, тесты, переносимый Git-коммит и сценарии подготовки/публикации. Готовой Windows DLL в этом исходном комплекте нет: она собирается с установленной игрой.

Нужны PowerShell 7, Git, GitHub CLI (`gh`) с авторизацией и Quasimorph `1.0.4.581s.2952480`. Скрипт проверяет точный SHA256 игры. Используется существующий публичный Workshop-предмет **3780078201** и репозиторий **Neversalimus/Quasimorph-Item-Intelligence**.

## 1. Собрать и зафиксировать файлы

Из распакованного комплекта выполните:

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\Prepare_QII_v1.7.42.4_Release.ps1
```

Если игра установлена в другом месте, добавьте `-GameRoot "X:\SteamLibrary\steamapps\common\Quasimorph"`.

Скрипт проверяет переносимый Git-коммит, создаёт отдельный checkout в `C:\QM_Workshop\_QII_RELEASE_SOURCE_17424`, проверяет актуальную remote main и запускает штатную RELEASE-сборку. Готовые файлы попадают в `C:\QM_Workshop\ItemIntelligence`, а их зафиксированная копия, ZIP, хеши и квитанция — в `C:\QM_Workshop\Frozen\ItemIntelligence-v1.7.42.4`.

Существующие исходники не удаляются. При повторном запуске допускается тот же чистый коммит; готовый комплект проверяется и используется повторно. Если подготовка прервалась до записи квитанции, сохраните эту папку и задайте новый `-OutputDirectory`. Если remote main изменилась несовместимо с принятым коммитом, скрипт остановится; не обходите проверку принудительной перезаписью.

Подготовка не публикует Steam, main/tag или GitHub Release. Дождитесь `STABLE RELEASE FROZEN` и сохраните показанный SHA256 DLL.

## 2. Обновить публичный Workshop

В консоли Quasimorph выполните команду, которую напечатал скрипт. Для стандартных путей:

```text
mod_updateworkshopitem 3780078201 C:\QM_Workshop\Frozen\ItemIntelligence-v1.7.42.4\payload FALSE
```

Дождитесь успешного обновления. Отключите DEV Item Intelligence, включите публичный Item Intelligence и перезапустите игру. В `Player.log` должен появиться:

```text
[ItemIntelligence] ACTIVE VERSION 1.7.42.4 (StableRelease17424).
```

Откройте F2 → Loot в кампании. Для проверенного набора игровых данных ожидается `[AmputationSources] slots=236, items=120`. Это короткая проверка доставки стабильной сборки; результаты функционального Test3 уже сохранены в `Support/RuntimeAcceptanceTest3.json`.

## 3. Завершить публикацию GitHub

После успешного обновления Steam и проверки стабильной версии выполните из распакованного комплекта:

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\Publish_QII_v1.7.42.4_GitHub.ps1 -WorkshopPublished
```

Если при подготовке выбрали другой `-OutputDirectory`, передайте публикации `-ReceiptPath "...\release-receipt.json"` из этой папки.

Скрипт повторно проверяет исходники и все зафиксированные файлы, атомарно обновляет main/tag с проверкой ожидаемых значений, загружает архив в черновик GitHub Release и скачивает его для проверки хеша. Только после этого черновик становится опубликованным. При обрыве повторите ту же команду с той же квитанцией; существующие совпадающие файлы используются повторно. `-WorkshopPublished` подтверждает выполненный шаг Steam, автоматической проверки Steam у GitHub-скрипта нет.

Сохраняйте checkout, staging и Frozen до завершения публикации. При проблеме пришлите вывод команды, `LAST_BUILD_VALIDATION.txt` из checkout и новый `Player.log`. Игровые DLL для этой сборки повторно не нужны.

## Самостоятельная сборка и область проверки

`ItemIntelligence\Install.ps1` собирает локальный публичный staging без публикации. Для полного выпуска с GitHub используйте сценарий выше, чтобы архив и Steam получили одинаковые файлы.

Статические контракты и тесты без игровых файлов:

```powershell
pwsh -NoProfile -File .\ItemIntelligence\BUILD_AND_STAGE.ps1 -Mode RELEASE -ContractsOnly
```

Общий статус игры остаётся `UNVERIFIED-COMPATIBLE`: подтверждены отдельные функции, а не вся игра целиком. Оценки контейнеров исключают бюджет, временный Tech и события локации; базовые шансы ампутации исключают улучшение на гарантированную аугментацию. Все результаты и ограничения перечислены в `FIX_REPORT_RU.md`.
